# 변경 기록 2026-11-19 — 남산 구현·연결(월드개발)
업무: 온라인 등산 신규 산 남산 · 4/4단계 「남산 구현·연결」. 앞 단계: 조사 `docs/남산/남산-지형-코스-자료-조사-2026-11-19.md`, 설계 `docs/남산/남산-코스-체험-설계-v1.md`, 그림 `docs/남산/남산-그림-에셋-v1.md`.
커밋만 했고 배포는 하지 않았다(대표 확인 뒤).

## 1. 사용자에게 달라지는 것
- 산 고르기에 **남산 카드**가 관악산 다음에 붙는다(「다음 산 준비 중」 칸은 사라짐). 그림은 왼쪽 봉우리·지그재그 코스·정상 전망탑, 밤이면 탑 불빛·도심 불빛 점, 오른쪽 꼬리표 「밤 전망 추천」. 글은 설계서 §8 그대로(265 m · 1.1 km · 30분 · 4곳 · 쉬움 · 「남산 정상에서 도장을 받아요」).
- 남산 「오르기」 → **`/hiking/namsan/`** 남산 화면. 백범광장 출발 광장 → 성곽 계단길 → 정상 광장까지 1:1 크기로 걷는다(자동 걷기 약 25분).
- 조작·화면은 관악산과 같은 공통 틀: 위 왼쪽 알약(정상까지 남은 거리·높이, 누르면 지도) + 시점 칩, 위 오른쪽 💬·☰(친구 부르기·지도·설정), 오른쪽 아래 빨간 큰 단추(걷기/멈추기) + 달리기, 왼쪽 아래 떠다니는 조이스틱, WASD·드래그·R·V·F·X.
- 스탬프 4곳(門 城 望 塔)은 가까이 지나가면 찍히고(정상 塔은 정상 광장에 들어서면), 정상 광장에 들어서면 완등 카드(관악산과 같은 도장 그림, 이름 남산) + 완등 기록(`gwanak-summits`의 `namsan`, 산 고르기 기록 줄에 나옴). 구간 이동으로 온 등산은 기록하지 않는다.
- 정상 광장은 전망탑 받침 밖을 자유롭게 걷는다. 이어 오르기(이 기기 `namsan-hike:v1`, `?multi` 주소는 저장 안 함).
- 자유 설정: 남산 카드의 「자유 설정」은 **남산 정상 완등(또는 개발 버전)** 으로 열리고, 출발 지점 칸 없이 날씨·시간·계절 + 「이대로 오르기」만. 고른 값은 남산 화면에도 적용된다(같은 탭 sessionStorage).
- 함께 걷기·채팅: 같은 함께 걷기 서버, **방만 남산 방**(`hiking:남산`). 입장 창에는 「남산 서버」 한 줄. 상태 칩은 「연결됨 · n명 · 남산 서버」.

## 2. 어떻게 붙였나(관악산·공통 입장 흐름·서버를 안 바꾸는 방법)
- **관악산 `main.js`는 손대지 않았다.** GPX·청크·즐길거리에 묶여 있어 산 하나를 끼우면 관악산 동작이 흔들린다. 남산은 별도 페이지(`hiking/namsan/index.html` → `src/namsan/game.js`)에서 공통 부품을 그대로 가져다 쓴다: 카툰 빛·하늘·도심·원경(`createToonStyle`·`setupRendering`·`loadLandscape`), 남산 그림(`buildNamsan`), 동동이(`loadToonHiker`), 조작(`input.js`·`view.js`), 공통 화면 틀(`ui-frame.js`·`hiking-frame.css`), 채팅(`hiking-chat-ui.js`), 함께 걷기(`multi-client.js`), 입장(`entry.js`·`server-pick.js`).
- **걷기 규칙** `src/namsan/namsan-walk.js`(three 없음): 노면 폭 안(계단은 측벽 안)·두 광장 안만 걷고 그 밖은 가장자리로 미끄러짐, 높이는 코스 높이(계단 윗면)·광장은 지형, 속도는 관악산과 같은 공식(`route.js` `speedFor`, 계단 0.5 m/s), 진행 거리는 지난 자리 둘레에서만 이어 재서 굽은 계단에서 높이가 튀지 않게.
- **입장 흐름은 그대로**: 산 고르기(관악산 페이지)가 꺼내 둔 입장 선택(허브 선택·지난 선택)을 sessionStorage `aoworld:namsan-entry`로 넘기고, 남산 페이지가 같은 `enterWith`로 들어간다. 허브에서 관악산 몇 서버를 골랐든 남산은 남산 서버로. 주소로 바로 왔으면 지난 선택 → 없으면 공용 입장 창 한 번.
- **서버 코드·서버 목록(`SERVERS`)은 그대로.** 남산 방은 목록 밖 방이라 서버의 옛 규칙(20명이면 저절로 남산-2)을 따른다. 입장 창 인원은 서버가 이미 주는 값으로 계산: 등산 전체 접속 − 관악산 서버 방 인원(`namsanHealth`). 남산에서 고른 서버는 체험별 「지난 선택」에 쓰지 않는다(관악산 입장이 엉뚱한 서버로 가지 않게).
- 도심 건물 중 남산 코스·공원 안 33동은 남산 페이지가 받을 때 거른다(공용 `city-grid.js`는 그대로). 관악산 원경의 「N서울타워」 모형은 숨기고 원경 땅은 남산 판 안에서만 내린다(그림 인계 §3 그대로). 관악산 풀밭은 붙이지 않는다.

## 5. 못 한 것 · 남은 것
- 실제 아이폰·안드로이드에서 열어 보기(메모리·발열). 헤드리스 수치는 실제 기기와 다르다.
- 발소리·환경음은 남산 화면에 아직 없다(소리 없음). 관악산 소리 파일은 관악산 노면·구간 표에 묶여 있어 그대로 못 씀 — 후속 제안.
- 친구 부르기 주소는 남산 방 번호 없이 남산 페이지 주소만 보낸다(공용 `invite.js`가 서버 목록 방만 넣음). 받은 사람은 같은 입장 흐름으로 남산 서버에 들어간다.
- 설계서의 재미 후보(퇴근길 야경·계단 세기·순환로)·차로 길·순환버스는 이번 범위 밖(대표 결정 대기 포함).
- 남산 방 인원 계산은 「등산 전체 − 관악산 서버 방」이라, 옛 `?multi=다른이름` 방에 있는 사람이 있으면 그만큼 남산 인원에 더해진다(드묾).
