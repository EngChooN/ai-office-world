## 1. 공유 상태 규칙(①)
### 1-1. 기계마다 무엇이 판 사이에 남나(추천안)
| 종류 | 판 사이에 남아 모두가 같이 보는 것 | 판마다 새로 하는 것 | 이유 |
|---|---|---|---|
| 봉 | 상자 자리·기울기·돌아간 각도, 이 상자를 옮긴 사람 수 | 집게 위치(늘 처음 자리) | 대표 결정. 「여러 판에 걸쳐 조금씩」이 이 기계의 재미(조사 ③) |
| 집게 | 인형 14개 더미의 자리·자세(가장자리에 **걸쳐 있는 인형** 포함), 남은 인형 | 집게 위치 | 실물 인형뽑기의 「누가 걸쳐 놓은 인형」 재미. 이미 물리 더미가 있어 더 만들 것이 적음 |
| 열쇠 | 없음 | 칸·열쇠 모두 판마다 처음 | 한 번에 판정이 끝나 이어받을 진척이 없음. 빈 칸을 공유하면 「희귀 칸이 비어 못 뽑음」만 생김 |
| 타이머 | 없음 | 숫자·문 | 진척 없음. 큰 인형은 기계마다 1종으로 늘 같음 |
- 지금 코드 사실: 집게 더미는 **손님마다 따로** 만들어집니다(같은 시작값 + 성공 횟수로 다시 쌓기). 그래서 지금은 내 화면의 더미와 남의 더미가 다릅니다. 공유하려면 서버가 더미 자리를 들고 있어야 합니다(§4).
- **보이는 규칙 = 판정 규칙**(v3 원칙) 그대로: 공유 상태도 실제 물리 결과만 씁니다. 몰래 쉽게·어렵게 바꾸지 않습니다.

### 1-2. 언제 처음으로 돌아가나(초기화, 추천안)
| 때 | 봉 | 집게 | 이름(조절값) |
|---|---|---|---|
| 성공 | 2.5초 뒤 새 상자를 처음 자리에 | 지금 규칙 그대로(남은 인형이 10개 아래면 다시 쌓기) | `bridge.refillSec` 2.5 |
| 아무도 안 씀 | **30분** 뒤 처음 자리로 | 30분 뒤 다시 쌓기 | `share.idleResetMin` 30 |
| 막힘(§6) | 기계가 비는 순간 처음 자리로 | 같음 | `share.stuckPlays` 6 |
| 서버 다시 켬 | 처음 자리(서버는 메모리에만 들고 있음) | 같음 | — |
| 날짜 | 바꾸지 않음(서버 모드). 30분 규칙만 | 같음 | — |
- 처음 자리는 **정해진 공정 범위 안에서 조금씩 다르게** 놓습니다(실물 가게도 놓는 자리가 조금씩 다름): 봉 상자 받침 여유 ±4mm·돌림 ±8°, 기울기는 늘 0. 아슬아슬 범위(§5)에는 절대 들어가지 않게 합니다. 서버가 정하고 모두에게 같은 값을 보냅니다. `bridge.startJitterM` 0.004 · `bridge.startJitterDeg` 8.
- 30분은 「붐빌 때는 뒷사람이 이어받을 시간, 한산할 때는 이상한 자세가 쌓이지 않을 시간」 사이의 추정값입니다.

## 2. 자리 잡기·기다리기 규칙(②)
### 2-1. 원칙
1. **한 기계에는 한 사람만.** 누가 쓸지는 서버가 정합니다(먼저 도착한 요청 하나). 흡연장 벤치 자리(`room-rules.js`)와 같은 방식입니다.
2. 자리가 풀리면 **기계 상태는 그대로** 남고, 다음 사람이 그 상태에서 시작합니다(이어받기).
3. 상태는 **판이 끝나 결과가 정해질 때만** 바뀝니다. 판 도중 상태는 구경용으로만 흘려보냅니다.

### 2-2. 흐름
1. 기계 앞에서 「한 판」 → 서버에 자리 요청(`mt`). 허락(`mo`)과 함께 지금 기계 상태를 받습니다. **코인은 허락 뒤에 뺍니다.** 1.5초 안에 답이 없으면 「연결이 느려요」.
2. 거절(`mn`)이면 「○○님이 먼저 앉았어요」 + 「옆 빈 봉으로 →」 / 「다음 차례로 기다리기」(v4 §4-2).
3. 판 끝 → 내 화면이 결과·새 상태를 보냄(`me`) → 서버가 검사(§6-2)하고 버전 +1, 모두에게 방송(`ms`). **방송이 나간 뒤에야** 다음 판·다음 사람이 시작됩니다. 8초 안에 안 오면 판 전 상태로 둡니다.
4. 「한 판 더」면 자리 유지. 다음 사람이 있으면 3판 뒤 양보 안내 + 다음 판 5초 늦춤(v4 §4-4 그대로).

### 2-3. 자리가 풀리는 때(추천안)
| 상황 | 풀릴 때까지 | 조절값 |
|---|---|---|
| 「그만」·✕ | 바로 | — |
| 서는 자리에서 1.5m 밖으로 걸어 나감 | **3초**(그 안에 돌아오면 유지) | `share.leaveSec` 3 |
| 결과·규칙 카드에서 아무 입력 없음 | 60초, **기다리는 사람이 있으면 20초** | `share.idleSec` 60 · `idleWaitSec` 20 |
| 다른 앱·탭으로 감 | 20초 | `share.hiddenSec` 20 |
| 연결 끊김 | **15초**(같은 사람이 다시 붙으면 이어감, 지금 resume 방식) | `share.dropSec` 15 |
| 10분에 3번 넘게 끊김 | 바로(맡아 두지 않음) | `share.dropMax` 3 |
| 판 도중 끊김 | **그 판은 없던 일**: 기계 상태는 판 전 그대로, 코인은 돌려줌(다음에 들어올 때). 자리는 위와 같이 15초 | — |
- 풀린 뒤 「다음 차례」 한 명만 10초 우선(v4 그대로), 지나면 누구나. 다음 차례는 한 사람이 한 기계만 걸 수 있습니다.
- 판 도중 끊긴 판을 없던 일로 하는 이유: 서버는 물리를 돌리지 않아 끊긴 판의 결과를 모릅니다. 남에게 손해가 없도록 「안 한 판」으로 둡니다. 끊어서 나쁜 판을 무르는 사람은 코인만 돌려받을 뿐 상태를 바꾸지 못합니다.

### 2-4. 부딪히는 경우 정리
| 경우 | 처리 |
|---|---|
| 둘이 같은 순간 「한 판」 | 서버에 먼저 닿은 한 명. 늦은 사람은 조작 화면에 들어가기 전에 거절 안내(코인 안 빠짐) |
| 앞사람 결과 연출 중 뒷사람이 시작 | 상태 방송(`ms`)이 나가기 전에는 기계 불이 「정리 중」(주황 깜빡)이라 시작 못 함 |
| 앞사람 판이 끝나기 전에 앞사람 연결이 끊김 | 판 무효 → 판 전 상태로, 15초 뒤 자리 풀림 |
| 이어받은 사람이 「처음 자리로」를 원함 | 손으로 되돌리는 단추는 두지 않음(남의 진척을 지울 수 있어서). 처음 자리는 §1-2 규칙으로만 |
| 구경하던 사람이 다음 차례 | 지금 구경 연출 그대로 보다가 자리 풀리면 10초 우선 |
| 타이머 성공 뒤 문이 열린 채 큰 인형이 받침에 있음(월드아트 v1.6: 결과 카드를 닫으면 0.5초 동안 닫힘) | 받침에 인형이 있는 동안은 **자리가 풀리지 않은 것**으로 봄. 자리가 풀리는 순간(「그만」·입력 없음 60/20초·걸어 나감 3초 등) 결과 카드를 저절로 닫고 문을 닫음 → 문이 다 닫힌 뒤(0.5초) 다음 사람 시작. 구경 화면은 지금처럼 2.5초 뒤 닫힘 |

## 3. 혼자 뽑기(서버 없음)일 때(③)
| 안 | 내용 | 판단 |
|---|---|---|
| **A. 이 기기에 저장(추천)** | 기계 상태를 이 기기 저장값(`claw-world:v1` 안 기계별 칸)에 두고 **오늘(서울 0시, 코인 채움과 같은 때)까지** 이어서. 자리 잡기·기다리기 없음 | 내가 하다 만 상자를 오늘 안에 다시 이어 할 수 있음. 하루 코인 15개면 상자 2~3개라 하루 단위가 맞음 |
| B. 가짜 앞사람 상태 | 새 상자를 「누가 하다 간 것처럼」 아슬아슬하게 놓음 | **비추천.** 없는 사람을 꾸미는 것이 되고, 일부러 「아깝다」를 만들어 더 하게 하는 꾸밈(니어 미스 유도)이 됨 |
| C. 처음 자리 조금씩 다르게 | §1-2 공정 범위 안에서만 | A에 덧붙임(서버 모드와 같은 규칙) |
- 혼자 모드는 30분 규칙이 아니라 「오늘까지」입니다. 규칙 카드에도 모드에 맞는 글을 씁니다(§5-6).
- 서버에 붙으면 **서버(가게) 상태가 이깁니다.** 이 기기 상태는 지우지 않고 따로 두었다가, 다시 혼자 모드가 되면 그것으로 돌아갑니다. 서버에 붙었을 때 둘이 다르면 「가게 기계 상태로 맞췄어요」 한 줄.
- 연결이 끊겨 혼자 모드가 되면 마지막으로 받은 서버 상태에서 이어서 하고(이 기기에 저장), 다시 붙으면 서버 상태로 맞춥니다.
- 「내 컴퓨터 모드」(같은 브라우저 창끼리, 시험용)는 지금처럼 「뽑는 중」만 보이고 상태는 창마다 저장합니다(공유 안 함). 시험용이라 서버 규칙을 다시 만들지 않습니다.

## 4. 서버가 켜졌을 때 주고받는 것(④, 월드개발 인계)
### 4-1. 기계 상태 모양(정수로 줄여 보냄, 크기는 시안 ⑨에서 잼)
| 종류 | 담는 값 | 한 번 크기 |
|---|---|---|
| 봉 | 버전, 상자 자리(mm 3개)·자세(1000배 정수 3개), 옮긴 사람 수, 진척 없는 판 수 | 약 **60바이트** |
| 집게 | 버전, 인형 14개 × [종류 번호, 자리 mm 3개, 자세 정수 3개] | 약 **400바이트** |
| 열쇠·타이머 | 버전만(자리 잡기용) | 약 15바이트 |
| 들어올 때 16대 전체(`ma`) | 위 합 | 약 **2.7KB**, 입장·다시 연결 때 1번 |
- 서버는 이 값을 **메모리에만** 둡니다(디스크 저장 없음). 서버를 다시 켜면 모두 처음 자리.
- 집게 더미 받는 쪽 주의: 받은 자리에 인형을 놓은 뒤 물리를 0.5초만, 흔들림을 크게 줄여 돌립니다(걸쳐 있는 인형이 기기마다 다르게 떨어지지 않게). 지금 물리는 점 묶음이라 각 인형의 자세(`frame`)로 점 자리를 다시 계산해 넣는 함수가 필요합니다.

### 4-2. 메시지(이름은 제안, 월드개발이 정함)
| 방향 | 이름 | 내용 |
|---|---|---|
| 손님 → 서버 | `mt` 자리 요청 {m} · `me` 판 끝 {m, n 판 번호, v 기준 버전, st 새 상태, res 결과} · `mf` 자리 놓기 {m} · `mq` 다음 차례 {m} | |
| 서버 → 손님 | `mo` 허락 {m, v, st} · `mn` 거절 {m, by} · `ms` 새 상태 방송 {m, v, st, by} · `mh` 자리 바뀜 방송 {m, by, nx 다음 차례} · `ma` 전체 {기계마다 v, st, by, nx} | |
| 판 도중 구경 | 지금 `act`에 칸 하나 더: 봉 = 상자 자세 `bx`, 집게 = 집게에 잡힌 인형 하나 자세. 미는 동안만 초당 8번(지금 act 한도) | 약 60바이트 |

### 7-9. 집게 기계 난이도 점검(11-23 물리 통과 수정 뒤, 월드디자인)
- 설계 목표: 집게 기계만 따로 정한 숫자는 없음. 가게 전체 목표 「보통 실력 4~6판에 하나 · 하루 코인 15개로 2~3개」(v4 §5)와 보장 「5번 실패 → 힘센 집게, 약 60%」(3D 손맛 설계 v2)를 기준으로 봄.
- 시험(월드개발과 같은 겨누기: 남은 인형 하나를 ±2cm 흔들어, 더미 40개 × 12판, **보장 포함**): 판당 성공 **20%**, 첫 성공까지 평균 **5.5판**·중간값 5판, 6판 안 26/40, 8판 안 30/40, **12판 안에 못 뽑음 4/40**. `artifacts/claw-design/side-review/claw-pity.mjs`

## 11. 손님 인형 자리(월드기획 추가 지시, 추천안·대표 미확인)
### 11-1. 무엇이 문제였나(코드에서 확인)
- 손님 인형 자리는 둘입니다(`claw-palette.js` `GUEST_SLOTS`): guest-1(특별, 공개판 대체 = 해치), guest-2(희귀, 공개판 대체 = 산고양이). 다른 회사 캐릭터용이라 **비공개판(`VITE_CLAW_PRIVATE=1`)에서만** 실제 인형이 들어가고 공개판에는 대체 인형이 놓입니다.
- 지금 guest-1은 별빛 열쇠 기계의 위 줄 오른쪽 끝 칸에 있습니다. guest-2는 도시 타이머 기계에 있었는데, 타이머 경품이 큰 인형 3종만으로 바뀌면서(월드아트 v1.6) **어느 기계에도 없게** 됐습니다.

### 11-2. 결정(추천안): 손님 인형은 열쇠 기계에만, 한 기계에 하나씩
| 자리 | 기계 | 칸 | 공개판 대체 인형 |
|---|---|---|---|
| guest-1(특별) | **열쇠 1 · 별빛** | 위 줄 오른쪽 끝(8번째 칸) — 지금 자리 그대로 | 해치(희귀) — 그대로 |
| guest-2(희귀) | **열쇠 2 · 달빛** | 위 줄 오른쪽 끝(8번째 칸) — 열쇠 1과 같은 자리 | **산고양이 → 회사원 동동이(희귀)로 바꿈** |
- 16대 구성(집게 6·봉 4·타이머 3·열쇠 3, 빈 자리 2)은 **그대로**입니다. 기계를 늘리거나 빼지 않습니다. 시안 ⑩ 표 점검 9개(16대 구성·작은 인형 8종·상자 8종·큰 인형 3종·손님 자리 한 기계씩·열쇠에만·대체 인형 구멍 크기·칸 8개) 모두 통과.

### 11-3. 근거
1. **열쇠 칸은 물리가 없습니다.** 집게·봉은 인형 몸을 물리로 계산하는데, 손님 인형은 모델(GLB) 또는 **그림 판**으로 들어옵니다. 물리는 우리 인형 몸 모양(곰·토끼·병아리)으로 계산되므로 손님 인형을 집게 더미에 넣으면 「보이는 모양 ≠ 잡히는 모양」이 됩니다(v3 원칙 「보이는 규칙 = 판정 규칙」 위반). 열쇠 칸은 칸에 앉아 있기만 하고 판정은 구멍 크기로 하므로 모양 차이가 판정에 안 들어갑니다.
2. **열쇠는 공유 상태가 없습니다(§1-1).** 집게 더미를 공유하면 같은 서버에 비공개판 손님(손님 인형, 희귀 0.28m)과 공개판 손님(대체 인형, 크기 다름)이 섞여 더미 모양이 기기마다 달라집니다. 열쇠는 판마다 처음이라 이 문제가 없습니다.
3. **타이머는 큰 인형 전용**이 됐습니다(대표 피드백). 손님 인형을 큰 판으로 만들면 다른 회사 캐릭터를 새로 크게 그리는 일이 되어 쓰지 않습니다. 봉 상자 피규어도 같은 이유로 넣지 않습니다(상자 그림을 새로 만들어야 함).
4. **가게 바닥·진열에는 두지 않습니다.** 못 뽑는 진열은 「왜 이건 안 돼요?」 헷갈림이 되고(장식 기계를 없애는 것과 같은 이유), 들어오자마자 보이는 자리라 촬영·릴스 화면에 다른 회사 캐릭터가 찍힐 일이 많아집니다. 빈 자리 A·B(문 옆)도 같은 이유로 쓰지 않습니다.
5. **한 기계에 하나씩, 같은 칸 자리**: 도감에서 「손님 인형은 열쇠 1·2의 위 줄 끝 칸」으로 찾기 쉽고, 비공개 점검(`check-claw-private.mjs`)에서 볼 곳이 두 칸뿐입니다.
6. **대체 인형을 회사원 동동이로 바꾸는 이유**: 열쇠 칸 구멍 크기는 칸 인형의 희귀도로 정해집니다(`keyCellRare`: 희귀·특별이면 작은 구멍). 지금 guest-2의 대체 인형 산고양이(보통)는 큰 구멍이라 **공개판과 비공개판에서 같은 칸의 난이도가 달라집니다.** 희귀인 회사원 동동이로 바꾸면 두 판 모두 작은 구멍으로 같습니다. guest-1 대체 해치(희귀)는 이미 같은 작은 구멍이라 그대로 둡니다.

### 11-4. 월드개발이 바꿀 것(바로 구현용)
1. `claw-palette.js` `GUEST_SLOTS`의 guest-2 `fallback: 'cat'` → `'dongdong-office'`.
2. 16대 목록(1단계)에서 `key-1.cells` = 지금 별빛 칸 그대로, `key-2.cells` = §12 값(8번째 칸 `guest-2`), `key-3.cells`에는 손님 자리 없음. 다른 종류(`claw-*`·`bridge-*`·`timer-*`)의 `pool`에는 `guest-*`를 넣지 않음.
3. `keyCellRare`가 손님 id를 볼 때 지금은 이름이 `guest-`로 시작하면 늘 「특별」로 봅니다. 자리 희귀도(`GUEST_SLOTS[].rarity`)를 쓰게 고치기를 권합니다(결과는 지금도 같은 작은 구멍이라 급하지 않음).
4. 도감: 손님 칸은 지금처럼 실제 인형이 들어왔을 때만 생김(`clawCatalog`). 배지 줄은 「인형」 하나만(큰 인형·상자 판이 없으므로).
5. 서버 검사(§6-2) 「인형 종류가 경품 묶음 안」은 **자리 id(guest-1·2)** 기준으로 봄(비공개판·공개판 손님이 같은 서버에 있어도 같은 값).
- 완료 기준: 공개 빌드에서 열쇠 1·2의 8번째 칸 = 해치·회사원 동동이, 둘 다 작은 구멍 / 비공개 개발 서버에서 같은 칸 = 손님 1·2 / 집게·봉·타이머 기계 어디에도 `guest-*` 없음 / `check-claw-private.mjs` 통과.
