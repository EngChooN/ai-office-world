# 변경기록 2026-11-20 — 관악산·남산 한 게임 통합 7단계 (월드개발)

월드기획 지시(11-20): 7단계 = 남산 전용 코드 더 줄이기, 휴대폰 메모리 재기, 두 산 함께 걷기 섞임 시험. 관악산 동작·화면 유지, 남산 확정 규칙 유지. 라디오 점검 흔들림 원인 확인. 휴대폰 세로 알약 글이 시점 칩에 닿는 문제는 제안만.

## 1. 공통 본체 부품으로 더 옮긴 것 (`src/hiking-body.js`)

두 산 파일에 같은 모양으로 따로 있던 코드를 한 벌로 모았다. 관악산 쪽은 글자 그대로 옮겨 동작이 같다.

| 부품 | 하는 일 | 전 |
|---|---|---|
| `readQualityMode`·`saveQualityMode`·`bindQualityControls` | 화질 고르기(저장 키 `gwanak-quality-mode`·`?quality=`·#quality 단추·`hiking:quality`) | main.js·game.js에 각각 |
| `installLifecycleSave` | 탭 숨김·창 흐림·닫힘·얼림 때 저장 | 각각 |
| `easeCameraZoom` | 쌍안경·휴대폰 배율 부드럽게 | 각각 |
| `paintHikeCard`·`hikeClock` | 진행 카드(상태·거리·남은 길·고도·시간·속도·예상 시간·노면·화질)와 걷기·기구·시점 단추 칠하기 | 각각(같은 자리·같은 글 모양) |
| `sceneMemory` | 장면 메모리 어림(관악산 `hiking.memory()`) | 관악산만 → 남산 `namsan.memory()`도 같은 셈 |

- `game.js` 573 → 561줄(64.6 → 63.8KB), `main.js` 71.2 → 68.6KB. 남은 `game.js`는 남산 세계(지형·그림·밤 불빛)·버스·자물쇠·야경 벤치와 남산 걷기 부품을 공통 HUD에 잇는 코드다.
- 작은 고침: 남산 쌍안경 「다녀온 산」이 읽는 관악산 완등 id를 이름 붙인 상수로(값 `gwanak` 그대로). 남산 시점 칩도 기구를 든 동안 「쌍안경을 쓰는 동안은 1인칭 고정」 풀이가 붙는다(관악산과 같은 동작, 남산은 휴대폰 카메라가 없어 글만 다름).
- 시험: `tests/mountain-body.test.mjs`에 2개(두 산이 새 부품을 쓰고 저장 키·숨김 저장이 한 곳에만 있음, 화질 주소 값·배율·시계 글).

## 3. 두 산 함께 걷기 섞임 시험 (`scripts/verify-two-mountain-multi.mjs`, 새 점검)

로컬 서버 하나에 관악산 2명(관악산-1)·남산 2명(남산-1)을 넣고 확인. 결과 `artifacts/merge-baseline/step7/namsan/two-mountain-multi/`.

- 명단: 같은 산 사람만 보임. 이름이 같은 두 사람(관악산·남산)도 서로 안 섞임.
- 서버 인원: 관악산 1서버 2명, 등산 전체 4명 → 남산 입장 창 2명.
- 채팅: 관악산 말은 관악산만, 남산 말은 남산만.
- 행동 상태: 남산 자물쇠(act `lk-…`)는 남산 상대만 받고 상대 화면에 걸림. 관악산 명단엔 없음.
- 동행 제안을 다른 산 사람에게 보내면 받는 쪽에 아무것도 안 뜸(서버도 같은 방만 받음).
- 관악산 사람이 같은 탭에서 남산으로 옮기면 관악산 명단에서 빠지고 남산 명단에 들어감, 위치도 남산 코스 근처.
- 서버 없이(같은 브라우저 창끼리)도 관악산 창·남산 창이 안 섞임.

## 4. 라디오 점검 흔들림 원인 (`scripts/verify-radio.mjs`, 라디오 코드는 안 고침)

측정 `artifacts/merge-baseline/step7/radio-probe/`(같은 페이지에서 20~12번 반복).

| 실패했던 항목 | 원인(측정으로 확인) | 고친 점검 |
|---|---|---|
| 볼륨 노브 0.2 → 0.9 커짐(6dB 넘게) | 91.9 곡은 대목마다 크기가 다름. 같은 볼륨에서 1.5초 평균이 최대 13dB 오르내림. 0.2를 1.5초 잰 뒤 0.9를 1.5초 재면, 곡이 조용해지는 대목에 걸릴 때 차이가 4dB로 줄었음(실제 볼륨 차이는 13dB, 12번 잰 차이 10~17dB) | 0.4초씩 번갈아 6번 재서 차이의 중간값으로 판정(기준 6dB 그대로) |
| 99.1 다음 파일로 끊김 없이 | 99.1은 원래 조용한 파일이 있어 넘어가는 사이 −49dB까지 내려감(6번 측정 최저 −36~−49). 기준 「−50dB보다 커야 함」이 그 파일에 너무 가까워 −50.0에서 실패 | 끊김 = 소리 없음(−∞)으로 보고 −65dB로, 「중간보다 15dB 넘게 꺼지지 않음」은 그대로 |

즉 라디오가 끊기거나 볼륨이 안 먹은 것이 아니라 재는 방법이 곡 내용에 흔들린 것. 벤치 쉬기 속도(trail-buttons)는 묶음 실행 때 시간 재기가 밀린 것으로 4·6단계와 같음(단독 재실행 통과).

## 6. 제안만 — 휴대폰 세로 진행 알약 글이 시점 칩에 닿음 (적용 안 함)

원인: 윗줄 폭이 `100vw − 140px`(세로 390이면 250px)인데 알약(최대 글 폭 200px) + 시점 칩(약 86px) + 사이 8px이 들어가야 해서, 알약이 줄어든 만큼 글이 알약 밖으로 삐져나와 칩에 닿는다. 두 산 같은 공통 틀(`src/hiking-frame.js/.css`) 문제다.

- **추천안(대표 미확인): 좁은 세로 화면(폭 ≤ 400px)에서만 알약 글을 짧게** — 「정상까지 1.1 km · 고도 106 m」 → 「정상 1.1 km · 106 m」, 관악산 「연주대 3.2 km · 250 m」. 그리고 혹시 더 길어지면 알약 안에서 말줄임(…)으로 잘리게(`overflow:hidden`). PC·가로는 그대로.
- 다른 안: 세로에서 시점 칩을 글자 없이 아이콘 원(44px)으로 — 칩 자리가 줄어 알약 글이 그대로 들어감. 시점 칩 「늘 보임」 규칙은 지키지만 글이 없어 처음 보는 사람이 덜 알아봄.
- 관악산 화면도 바뀌므로 적용 전 월드기획·대표 확인 필요.
