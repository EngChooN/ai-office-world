# 변경 기록 2026-11-17 — 흡연장: 상호작용 단추가 안 눌리는 문제, 같이 피우기에서 모두에게 같게

지시(대표): ① 흡연장에서 상호작용 버튼을 눌러도 아무 반응이 없음 ② 멀티에서 누가 누르든 접속한 모두에게 같게(다른 사람 것도 내 화면에, 나중에 온 사람도 지금 상태, 동시에 눌러도 안 엉키게 = 서버가 판정). 「알아서 끝까지, 묻지 말고」.
커밋은 작업 가지에만 했고 push·배포는 하지 않았습니다.

(가) **`<html data-scene>`이 단추 처리를 가로챔.** 상황을 고르면 `scene.js`가 분위기 색을 위해 `<html data-scene="evening">`처럼 맨 위 요소에 표시를 답니다. 그런데 `spots.js`의 클릭 처리는 맨 먼저 `e.target.closest('[data-scene]')`로 「상황 고르기 단추를 눌렀나」를 봤고, 이 찾기는 단추가 아니어도 `<html>`까지 올라가 걸립니다. 그래서 상황을 한 번이라도 고른 사람은 옥상 할 일 단추를 누를 때마다 「같은 상황 다시 고르기」만 일어나고 정작 할 일은 안 됐습니다. 입장하면 상황 창이 먼저 뜨고, 지난번 상황은 다음 방문에 저절로 이어지므로 **사실상 모든 사용자가 겪는 고장**입니다.
 - 11-08 메타버스 통합 때부터 있던 결함입니다. 그동안의 점검 스크립트는 주소에 `?time=`을 붙여 상황 창이 안 뜨는 상태로 눌러서 못 잡았습니다.
 - 고치기 전 코드로 다시 해 봐도 같았습니다: 상황을 고른 뒤 자판기·벤치 표시를 눌렀을 때 캔 없음·서 있음 그대로, 상황 단추도 안 열림(휴대폰 탭).

(나) NPC를 부르지 않는 기본 옥상(11-08 대표 요청)에서는 `npcs.social()`이 `null`인데, G 키 처리만 `npcs.social?.().incoming`으로 바로 읽어 오류가 났습니다.

**아이콘 교체(7e9b1fa·abf11a1)는 원인이 아니었습니다.** `git diff 126c3eb abf11a1 -- src/lounge`를 보면 단추의 `data-a`·`data-sp`·`data-k`·클래스·처리 함수는 그대로이고 그림(이모지 → `<svg><use>`)과 글만 바뀌었습니다. 글자로 상태를 비교하던 꾹 단추도 `data-q`로 바르게 바뀌어 있었습니다. 다만 아이콘 그림(`<svg><use>`)이 눌린 대상이 되면 옛 사파리 일부는 `event.target`을 이상하게 주므로, 아이콘 그림은 누르는 대상이 되지 않게 했습니다(아래 §2-①).

## 4. 확인 못 한 것
- **실제 아이폰 사파리·안드로이드 기기**에서는 눌러 보지 못했습니다(자동화 브라우저의 휴대폰 크기·터치 흉내까지). 옛 사파리의 `<svg><use>` 대상 문제는 CSS로 막았지만 실제 옛 기기는 없습니다.
- **운영 멀티 서버(8787)는 지시대로 건드리지 않았습니다.** 새 판정은 다시 켠 뒤부터 적용됩니다(§2 끝).
- 인터넷(터널) 너머의 지연이 큰 상태에서 동시 누르기는 로컬 서버로만 봤습니다. 판정은 서버가 받은 순서라 지연과 관계없이 한 사람만 차지하지만, 늦은 사람은 잠깐 앉았다 일어서는 모습이 보일 수 있습니다.
- NPC를 켠 옥상(`?npc=1`)의 불 빌리기·한 대 권하기는 NPC가 각자 화면에만 있어 나누지 않았습니다(기본 옥상에는 NPC가 없음).
