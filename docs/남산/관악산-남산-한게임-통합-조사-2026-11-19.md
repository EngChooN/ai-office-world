# 관악산·남산을 한 게임으로 합치는 조사 (2026-11-19)

대표 지침 「같은 게임에서 산(맵)만 달라지는 것이고, 기존 기능이 없어지면 안 된다」를 근본적으로 지키려면 코드를 어떻게 바꿔야 하는지 조사했습니다.

- **코드는 고치지 않았습니다.** 파일을 열어 읽고 줄 수·글자 수를 세기만 했습니다. 화면은 띄우지 않았습니다.
- 표시: **[확인]** = 파일을 열어 직접 본 것, **[추정]** = 읽은 내용을 바탕으로 한 어림(작업 일수는 모두 추정).
- 함께 볼 문서: `docs/남산/남산-관악산-기능-비교표-2026-11-19.md`(119개 중 남산에 있음 42·일부 19·없음 58), `docs/변경기록-2026-11-19-남산-구현-연결.md`.

## 1부. 대표용 요약 (쉬운 말)

### 1-1. 지금은 어떻게 되어 있나

- 관악산과 남산은 **같은 부품(그래픽·동동이·조작·채팅·함께 걷기)을 쓰지만, 게임을 굴리는 "본체"가 두 개**입니다.
  - 관악산 본체: `src/main.js`(573줄, 약 77KB) + 걷기 규칙 `src/movement.js`(245줄).
  - 남산 본체: `src/namsan/game.js`(285줄) + 걷기 규칙 `src/namsan/namsan-walk.js`(148줄).
- 남산 본체는 관악산 본체를 **간단하게 다시 쓴 것**입니다. 남산 `game.js` 285줄 중 약 230줄(약 80%)이 관악산 `main.js`가 하는 일(화면 준비·카메라·동동이 움직이기·함께 걷기 연결·매 프레임 처리)을 줄여서 다시 한 것이고, 남산에만 필요한 줄은 약 50줄입니다. [확인: 줄 단위로 맞대어 봄, 비율은 어림]
- 그래서 **관악산에 기능이 하나 생기면 남산에도 따로 한 번 더 만들어야** 하고, 지금 비교표의 "없음 58개"가 바로 그 밀린 숙제입니다.
- 관악산 본체가 남산을 그대로 못 받는 이유는, 관악산 본체가 **관악산 자료를 파일 맨 위에서 바로 불러다 박아 넣는 구조**이기 때문입니다(GPX 337점 코스, 입구 광장·일주문, 정상 구역, 스탬프 6곳, 즐길거리 자리, 동물 구역, 쌍안경 관측점, 밤 가로등 자리, 환경음 구간표 등). [확인]

### 1-2. 합치면 어떻게 되나

- 게임 본체를 하나로 두고, 산마다 **「산 정의」라는 자료 묶음** 하나만 따로 둡니다. 산 정의에는 "지형·코스·어디를 걸을 수 있나·높이·스탬프 자리·안내판 글·즐길거리 자리·쌍안경 관측점·밤 가로등 자리·환경음 구간·출처 문구·로딩 문구" 같은 것이 들어갑니다.
- 그러면 관악산에 새 기능을 넣는 순간 남산에도 같이 생깁니다. 산에 따라 다른 것(예: 남산엔 계곡이 없음)은 산 정의에서 "없음"으로 끄면 됩니다.
- 새 산을 더할 때는 **지형 자료 + 코스 + 그림 + 산 정의 자료**만 만들면 되고, 게임 화면 코드는 새로 쓰지 않습니다.

### 1-3. 얼마나 걸리고 무엇이 위험한가 (모두 추정)

| 항목 | 어림 |
|---|---|
| 합치는 작업 전체 | **약 17~26 사람-일**(숙련 개발자 1명 기준 3.5~5주). AI 직원이 하면 코드 쓰는 시간은 줄지만, 두 산 점검(스크립트 약 40개 + 휴대폰 확인)에 드는 시간은 크게 줄지 않음 |

| 막는 법 | 단계를 아주 작게 쪼개고, 단계마다 관악산 점검 스크립트를 돌림(3부 6절 목록). 저장 키 이름은 하나도 바꾸지 않음 |

### 1-4. 순서 제안 (요약)

지금 하고 있는 이식은 끝까지 하되, **복사해 붙이지 말고 "공통 함수로 빼서 두 곳이 같이 부르게"** 하면 합치기 비용이 줄어듭니다. 이식이 끝나면 아래 순서로 합칩니다. 각 단계가 끝날 때마다 두 산 모두 지금처럼 돌아갑니다.

1. 지금 상태 기록(관악산·남산 점검 결과와 메모리 수치를 기준으로 남김)
2. 배경(서울 도심·한강·원경)과 관악산 산(지형·입구·정상·소품)을 나눔 → 남산이 관악산 산 그림을 몰래 불러오던 것을 끊음
3. 관악산 자료를 「관악산 산 정의」 하나로 모음 → 관악산 본체가 그것을 읽게 바꿈(동작은 그대로)
4. 화면(수첩·지도·구간 이동·자유 설정)이 산 정의에서 글·숫자를 읽게 바꿈
5. 걷기 규칙을 "산마다 바꿔 끼우는 부품"으로 만듦(관악산 걷기·남산 걷기 둘 다 그대로 감쌈)
6. 남산 산 정의를 채움(스탬프·밤 조명 자리·환경음 표 등)
7. 남산 페이지를 공통 본체로 바꾸고 `game.js`의 중복을 지움
8. 두 산 모두 점검·휴대폰 메모리·함께 걷기 섞임 시험

### 1-5. 새 산 하나 더할 때 (추정)

| | 지금 구조 | 합친 뒤 |
|---|---|---|
| 합계 | **약 26~45 사람-일**(관악산과 기능을 같게 맞추기까지) | **약 7~15 사람-일** |
| 차이가 나는 곳 | 게임 화면 코드를 새로 쓰고, 관악산 기능을 다시 하나씩 옮겨야 함 | 지형 자료·코스·그림·산 정의 자료만 |

### 2-3. 합치는 구조안

#### 기본 모양


#### (3) 함께 걷기 방

- 방은 지금처럼 산마다 따로(`hiking:관악산`·`-2`·`-3` / `hiking:남산`)입니다. 같은 게임 좌표라 섞이면 받는 쪽이 자기 지형으로 높이를 구해 사람이 땅속·공중에 뜹니다(`namsan-walk.js` 12~15줄 주석). 서버 코드는 바꿀 필요 없습니다. [확인]
- **주의할 함정** [확인]: `multi-client.js`는 다른 사람을 **"같은 구역(zone)"일 때만** 가까운 사람·그림 대상으로 셉니다(104·240·313줄). 남산은 지금 늘 `zone:'plaza'`를 보냅니다(`game.js` 183). 합치면서 남산 걷기 부품이 `'route'`를 보내게 바꾸면, 배포 직후 옛 페이지를 열어 둔 사람과 새 페이지 사람이 서로 안 보일 수 있습니다. → 남산 걷기 부품은 처음엔 지금과 같은 구역 값을 보내고, 바꿀 거면 별도 단계에서 바꿉니다.
- 동행(나란히 걷기)은 `multi-client.js`가 `local.sample`·`minS`·`maxS`로 코스 위 자리를 계산합니다(263줄). 남산 걷기 부품이 `sample`을 주면 남산에서도 동행이 살아납니다(지금은 `sample:null`). [확인 + 추정]
