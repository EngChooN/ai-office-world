## 3. 붙이는 법(월드개발)
```js
import {loadNamsanData,createNamsanGround,courseAt,NAMSAN} from './namsan/namsan-data.js';
import {buildNamsan} from './namsan/namsan-art.js';
const data=await loadNamsanData(`${import.meta.env.BASE_URL}assets/shared/namsan/`);
const G=createNamsanGround(data);                 // G.ground(x,z) = 화면 땅 높이(코스 회랑 깎기·광장 평평·숲 칸 −7m 반영)
const ns=buildNamsan({G,data,toon,mobile});       // toon = createToonStyle 결과. 안에서 toonify까지 함
scene.add(ns.root);
// 매 프레임: ns.update(초, 밤 정도 0~1)  ← 전망탑 색 바꾸기·등불·광장 가로등. 밤 정도는 environment.current.night
```
- **걷는 높이:** 코스 위는 `courseAt(G.points,s).y`(계단도 이 값, 단 윗면은 이 값 ±8cm). 코스 밖·광장은 `G.ground(x,z)`. 계단 밑 땅은 0.25m 낮춰 두었습니다.
- **좌표:** 관악산과 같은 게임 좌표(`assets/realistic/geo.js` 원점, 1m, −Z 북)입니다. 남산은 원점에서 약 (3.1~3.7km, −9.2~−9.6km). 도심 건물·원경·한강 자료를 그대로 쓰고, 두 산이 서로 보입니다. 큰 좌표라 float 정밀도는 1mm 수준(문제없음, 추정).
- **자리 목록:** `ns.furniture.userData.items`(이정표·스탬프·표지석·쉼터 x,z·방향), `ns.lanterns.userData.spots`(등불 38곳), `ns.stairs.userData.runs`(계단 구간 s0~s1·단 수), `G.plaza`·`G.startPlaza`(중심·반지름·높이), `NAMSAN.tower`(전망탑 자리).
- **남산 화면에서 해야 할 것(관악산 쪽 자료와 겹침):**
  1. 관악산 원경의 「남산·N서울타워」 모형 숨기기, 원경 땅(160m 격자)을 남산 판 안에서 내리기 — `preview.js`의 `SeoulFar` 처리 3줄 그대로.
  2. 도심 건물 중 `city-hide.json` id 빼기. 지금 `createCityGrid`의 `exclude`는 자리·반지름 방식이라 id 거르기 옵션이 필요합니다(미리보기는 받을 때 거름).
  3. **관악산 풀밭(`toon.attachLandscape`)은 붙이지 마세요.** 관악산 길·입구·계곡 물 자리를 따르는 코드라 남산 계단 위에 풀이 납니다. 남산용 풀밭은 `grass-field.js`에 길·막힘 판정을 넘기는 옵션이 필요합니다(공용 파일이라 손대지 않음).
- **휴대폰:** `buildNamsan({mobile:true})` = 지형 간격 2배, 가까운 나무 60m만 LOD1, 코스 200m 밖 나무 절반. 미리보기 390×844에서 한 화면 삼각형 220만~360만·그리기 260~840번(도심 포함, 그림자 포함). 남산만 JS 메모리 약 170MB, 도심 28묶음 포함 540MB(관악산 게임과 같은 도심). **실제 아이폰은 확인 못 했습니다.** 숲은 400m 칸으로 나눠 화면 밖 칸을 안 그리지만, 관악산처럼 200m 청크 스트리밍으로 바꾸는 것을 추천합니다.

## 4. 설계서와 다르게 한 곳
| 설계서 | 그림 | 이유 |
|---|---|---|
| ①② 출발~400m 「성곽을 오른손에」 | 성곽은 **670~990m**(큰 계단 끝·쉼터·마지막 계단) 오른쪽 | OSM 성곽 자료가 이 구간에만 코스 옆을 지남. 0~650m 옆에는 자료에 성곽 없음 → 지어내지 않음 |
| 쉼터 ④ 810m 남서쪽 트임 | 770m, **성곽 쪽**에 데크 + 그 자리 성곽을 낮춘 전망 단(±7m) | 쉼터 쪽에 성곽이 바로 붙어 있어 3.6m 성곽이 전망을 막음 |
| 스탬프 0·600·810·1,060m | 8·600·790·1,060m | 출발 광장 판석 위·쉼터 데크 옆에 두려고 옮김 |
| 정상 방향판(정상 광장) | 1,030m 코스 옆 | 코스 끝이 전망탑 받침에서 약 20m라 광장 안 자리가 좁음 |
| 정상 높이 265m | 게임 정상 광장 바닥 **264.3m**(표지석·카드는 265m 표기) | 지형 자료에서 숲 높이(7m)를 뺀 값. 표기 기준과 1m 안 |

## 5. 실루엣 대조(사진 `artifacts/namsan-silhouette/`)
같은 카메라에서 **빨간 점선 = 실제 지형 자료(Copernicus DSM, 깎기 없음)**, **하늘색 선 = 게임 화면 윤곽(땅+숲)**, 노란 점선 = 게임 땅만을 그었습니다.
| 방향(거리) | 게임 윤곽 vs 실제 평균 | 최대 |
|---|---|---|
| 남쪽 한강 쪽(3.6km) | 2.5m | 10.2m |
| 서쪽 서울역 쪽(3.4km) | 2.1m | 29.0m |
| 북쪽 명동 쪽(2.8km) | 2.8m | 10.6m |
| 동쪽 장충동 쪽(3.6km) | 2.6m | 27.2m |
- 최대값이 큰 곳은 정상 광장 둘레(광장을 평평하게 하고 나무를 비운 자리)와 숲 가장자리 큰 나무 한 그루씩입니다(사진에서 확인).
- 처음에는 지형 자료(나무 높이 포함) 위에 나무를 또 심어 평균 7~9m 높았습니다 → 숲 칸 땅을 7m 낮춰 맞췄습니다(그래서 노란 선이 빨간 선보다 조금 아래).
- 위에서 본 대조 `plan-course-wall.png`: OSM 코스·성곽 원자료 선이 게임 길·성곽과 겹칩니다(성곽은 길과 겹치는 곳만 2.8m 비킴).
- 이 대조는 지형 자료끼리 비교입니다. 사진·로드뷰와는 비교하지 않았습니다(로드뷰 캡처 사용 불가, 조사 §6).

## 6. 확인한 것 / 못 한 것
- 확인: 미리보기 낮·노을·밤, 가을·겨울, PC 1600×900·휴대폰 390×844 장면 촬영(`artifacts/namsan-art/`), 실루엣 4방향 + 위에서 1장, 새 점검 5개 통과, 기존 단위 테스트 1,029개 모두 통과, 페이지 오류 0(404 1건은 미리보기 favicon, 추정).
- 못 함: 실제 게임 화면 연결·걷기(월드개발 몫), 실제 휴대폰, 산 고르기 카드 그림(`mountainArt`, 월드개발 몫), 함께 걷기 화면.
- 남은 문제: OSM 건물 중 공원 가장자리 건물(코스 40m 밖)은 그대로 남아 관악산 DSM 높이에 서 있습니다(멀리서만 보임). 백범광장 쪽 성곽은 OSM에 없어 넣지 않았습니다 — 넣을지는 월드기획 판단이 필요합니다.
